# Leonidas: gotchas and session notes (read on demand)

Moved out of [agent-playbook.md](../agent-playbook.md) so it is not loaded every turn. Search it before touching updater, release, rebrand, worktree, build-preflight or quota code.

## Gotchas already paid for

- **Watchdog forcefully crashing the renderer causes an infinite reload loop (2026-10-19):** RendererHangRecovery.ts pinged the renderer every 5 s and called webContents.forcefullyCrashRenderer() after 30 s of silence. Under normal load (initial rehydration, history rendering, GC) the renderer's V8 thread pauses or misses pings, triggering the crash. Each crash forces a reload, which incurs another heavy boot, causing another timeout after the 3-minute cooldown, looping forever. Retired: renderers must not be forcefully crashed by a timer.

- **The dev app hung on the loading screen for ever (found 2026-10-16):** the `Leonidas Code Dev Server` scheduled task ran at Windows priority 7 (below normal). Vite and its dependency optimizer starved at 0% CPU and never answered. The same start from a normal session took 10 s. `Install-DevShortcut.ps1` now sets `-Priority 4`. Other causes fixed the same day: `@clerk/clerk-js` in `optimizeDeps.include` does not resolve in `apps/web` (now filtered), React Compiler ran in dev (now build only, `LEONIDAS_DEV_REACT_COMPILER=1` turns it on), and `dev-live` was 1,453 files behind main (the supervisor now syncs it after 20 s of quiet in main). The boot splash in `apps/web/index.html` now shows progress, Retry and a copyable fix prompt for an agent.
- **A new RPC method needs 4 entries, not 2:** besides `rpc.ts` and the `ws.ts` handler, add it to `apps/server/src/auth/RpcAuthorization.ts` and `apps/server/src/observability/RpcInstrumentation.ts`. Without them the server rejects the call and the page shows its empty state with no error. The server typecheck reports the gap, so read every `error TS` line, not only the ones in the folder you changed.
- **The dev app's scheduled task can stall before it starts the runner:** in October 2026 `Leonidas Code Dev Server` sat for more than 15 minutes with no child process, while the same `Run-LeonidasDevServer.ps1` started at once from a normal session (`Start-Process pwsh -WindowStyle Hidden -File ...`). Each restart that comes from a server file edit also costs a full `vp run` start, so do not edit server files in `C:/lcw/dev-live` while it boots.
- **Dev page fails with "not exported" from `@pierre/diffs`, or the dev server will not start:** an interrupted `pnpm install` left a patched package without its patch while pnpm still treats it as current. `scripts/Run-LeonidasDevServer.ps1` now checks every `patchedDependencies` entry before each start (about 0.2 s) and rebuilds any copy missing its patch. By hand: delete its `node_modules/.pnpm/@pierre+diffs*` folders, run `pnpm install --frozen-lockfile`, restart the dev task. A clean install takes about 15 seconds; never kill one midway.
- **"A Leonidas server is already running" with nothing listening:** a stale `server-runtime.json` whose PID was reused by another process. The start guard now also checks that the recorded port answers; if you hit it on an old build, move the file aside.
- **The popup bullets are the GitHub release body:** `scripts/leonidas-release.ts` writes `notes.md`: up to 5 highlight `- ` bullets (`Release-Note:` trailers first, then cleaned subjects of commits without one; internal `ci/chore/refactor/test/docs/style/sync` subjects are skipped), an optional `## Details` list (overflow plus `Release-Detail:` trailers) and a last `<!-- leonidas-release {...} -->` metadata line (commit, authors, coAuthors). Wording standard: the leonidas-release skill. `apps/desktop/src/updates/releaseNotes.ts` stops reading at the `## Details` heading, so the popup shows highlights only (fixed in v0.9.0); it still reverses the list and keeps 8, so highlight order in the popup is unchecked live. No notes means the old toast shows. Notes cover only the newest release, so skipped versions are not listed. The "Read more" links point at `ItzJsimp/leonidas-code` releases (`DESKTOP_RELEASE_HISTORY_URL` in `desktopUpdate.logic.ts`, asserted in 3 test files).
- **Test the popup any time:** Settings > About > "What's new popup" > Preview opens it with the latest published release's bullets and no install buttons (`desktop/whatsNewPreview.ts`). Every push to `main` ships to the other machine through the same release feed.
- **No `vp` on PATH:** run `node_modules/.bin/vp test run <files>` and `node_modules/.bin/tsc --noEmit -p .` from `apps/web`.

- **Identity link needs a manual approval:** `CLAUDE.local.md` in the repo imports the user's AIOS, but external imports stay silently unloaded until `claude` is run once in the folder and the dialog is approved (per path, so redo after a rename). Escape spaces as `\ ` in `@` paths. Standard: [`project-standard.md`](../../../standards/project-standard.md) section 9.
- **Do not rebuild the update toast:** it already exists end to end; the only gap is publishing releases from our repo. Found 2026-10-09 by reading source before planning.
- **Keep the `claude` CLI installed:** the Claude provider runs the Claude Agent SDK, which is what loads `CLAUDE.md`, hooks and skills.
- **`New-Task.ps1` YAML escaping:** Windows paths in `-StartFiles` or quotes in `-Verify` broke card frontmatter before `c1eb7bab7`; fixed with `ConvertTo-YamlDq`. Use forward slashes in card paths anyway.
- **Upstream workflows need upstream secrets:** `release.yml` runs on a 30-minute cron and expects macOS signing, Azure signing and Clerk keys; disable it in the shared repo or it fails every half hour.
- **Two Claude accounts do not share threads:** threads only switch between instances with the same `CLAUDE_CONFIG_DIR`, so hitting one account's limit means a new thread on the other; load balancing spreads machines, not accounts. Source: [`project/settings-walkthrough.md`](../project/settings-walkthrough.md).
- **Launch arguments beat the permission picker:** `--permission-mode` or `--dangerously-skip-permissions` in a Claude instance's launch args silently override the UI choice; default permission mode is Full access.
- **Settings seed does not exist:** T3 has no team-defaults mechanism; settings sit in `~/.t3/userdata` (server `settings.json`, client `client-settings.json`, `desktop-settings.json`, `keybindings.json`). Map, never-ship list and seed design: [`project/settings-inventory.md`](../project/settings-inventory.md). The default `branchNamePrefix` is `t3`; change it with the rebrand.
- **Keep "T3 Connect" and its Account sheet:** it names upstream's hosted relay and sign-in (`clerk.t3.codes`), so renaming it would claim a service we do not run. Rebrand only the app's own name ("Sent by Leonidas", restart messages, widget text). Agent-facing MCP tool text ("inside a T3 thread") and marketing legal pages written for T3 Tools, Inc. are also left alone. Found 2026-10-12 by a tiered-agent branding scan.
- **Rebrand scope rule:** change user-visible names only; leave `@t3tools/*`, `T3CODE_*` env vars and the `~/.t3` / Electron userData folder names, or existing threads and settings orphan and upstream merges get costly.
- **Keep the app id `com.t3tools.t3code`:** changing it gives a new NSIS GUID, so installs land side by side and old T3 shortcuts survive; the runtime AUMID must match it or taskbar pins duplicate.
- **A push to `main` ships a release:** an agent pushes by itself when all checks pass (ADR "Agents auto-ship when checks pass", 2026-11-06). Run typecheck, scoped tests and `node scripts/smoke.mjs` first.

- **Claude "no subscription limits" was a 429:** the SDK `get_usage` returns `rate_limits_available: true, rate_limits: null` when Anthropic's usage endpoint is rate limited; that must map to `probeFailed` (retryable), never `unsupported` (sticky, drops streamed `rate_limit_event`s). Antigravity has no reachable quota source: the harness credential gets 403 on `fetchAvailableModels` and `retrieveUserQuota`. Found 2026-10-10.
- **Fresh worktrees need an install before any check:** `git worktree add` skips the T3 setup script. Run `pnpm install --frozen-lockfile` first (about 7.5 minutes); tests and typecheck fail until it finishes. Found 2026-10-11.
- **A commit that hangs is usually the hook, not git:** the Vite pre-commit hook runs `vp fmt` on staged files and can stall on a shared temporary index. Commit from a clean worktree and let the hook finish; never bypass it. Found 2026-10-11.
- **`shadcn/no-restyle` rejects `className` on `Button` and `MenuItem`:** use a `size` such as `icon-xs`, or a plain wrapper for layout. Use the `text-3xs` token, not `text-[10px]`. Found 2026-10-11.

- **Windows desktop preflight is not a dry run:** `node scripts/build-desktop-artifact.ts --platform win --target nsis --arch x64` runs the full build unless its prerequisite probe fails first. The probe reads `KitsRoot10` under `HKLM:\SOFTWARE\Microsoft\Windows Kits\Installed Roots`; on this machine it points at `C:\Program Files\Windows Kits\10\` (no `Lib`) while the SDK sits under `Program Files (x86)`. Spectre libraries live at `VC\Tools\MSVC\<ver>\lib\spectre\x64`. Found 2026-10-11.
- **Node-spawned PowerShell drops backslashes:** a `-Command` probe with `\` paths exits 1 with no stderr. `windowsVswherePrerequisiteScript` in `scripts/build-desktop-artifact.ts` uses forward slashes; that fix was uncommitted when written. Debug a probe by printing each step, not by re-running the whole string.
- **Isolated dev desktop and model catalog propagation:** launching `scripts/dev-isolated.ps1 -Mode desktop` does not prove that the caller MCP is connected to that dev instance. Check `orchestrator_capabilities` each time and require the exact model ID before delegation. Earlier checks omitted Apodex; the 2026-10-11 continuation advertised `apodex/apodex-1.1-mini:free` on `openrouter` and one synthetic Read/Write/read-back task passed, independently verified on disk. Never substitute `openrouter/auto`. The installer at `release/Leonidas-0.0.45-x64.exe` (supplied build commit `54340e9754`) was not installed during this check; catalog visibility is not installer acceptance proof.
- **Commit with a pathspec in the shared checkout:** other agents stage files in the same index, so a bare `git commit` sweeps their staged work into yours (a staged `packages/jev-router` deletion rode into one of mine). Use `git commit -m ... -- <paths>`, check `git show --stat HEAD`, and push from a clean `git worktree add --detach C:/lcw/<name> origin/main` plus `git cherry-pick` so only your commit goes. `git add -A` is blocked by a hook. Found 2026-10-13.
- **`pnpm install` in the main checkout is blocked by `scripts/guard-main-install.mjs` (root `preinstall`):** it refuses when a working `node_modules` exists, because the install wipes it and the dev app fails for 20+ minutes on a slow D: disk. Install in a worktree under `C:/lcw`. Only if you must: `LEONIDAS_ALLOW_MAIN_INSTALL=1 pnpm install --frozen-lockfile`. The dev supervisor sets this itself for its patch repair. Added 2026-10-15.
- **"Your desktop is not connected" in the dev app means the dev server is down:** a `pnpm install --frozen-lockfile` in the main checkout deletes `node_modules`, the server fails to restart (`Failed running 'src/bin.ts'` with no reason in `.t3/dev-server.log`) and every task action fails with a misleading connection toast. Confirm with `curl http://localhost:15733/.well-known/t3/environment` (502) and `ls apps/server/node_modules`, wait for the install, then `touch apps/server/src/bin.ts` to restart. Found 2026-10-13.
- **Tasks: practice before real clicks:** "Send to agent" starts a real agent with real tokens and "Share with collaborators" publishes the card to the public repo. Use the Practice project (rail, bottom) to try the flow; its Send is a dry run. Found 2026-10-13.
